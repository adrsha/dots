## Architecture and notification behavior

- Root selects `IllogicalImpulseFamily` via lazy panel-family loader. Family composes separately loaded background, bar, dock, notification popup, sidebars, wallpaper selector, settings, OSD and overlays. Its *bar is configurable*; our bar-free requirement stays intact.
- `Notifications.qml` tracks multiple live notifications, records timeout per entry, exposes popup list and app-group models, saves history to file, counts unread, inhibits popups when sidebar open/silent, offsets IDs after restart. Popup view uses a list rather than one replaceable card; grouping by app condenses volume. It does not present inline reply in reviewed code; our existing reply support should stay.
- Popup `PanelWindow` uses overlay layer, transparent window, full-screen anchors and input `mask` limited to list content; screen follows focused Hyprland monitor. No `WlrKeyboardFocus.OnDemand` on passive popup. Notifications stack simultaneously; list can anchor six screen positions. `NotificationGroup` caps collapsed group at ~80 px, uses 10 px padding, 10 px row spacing, radius token 17; expansions reveal individual items with 12 px inner radius and layered surface. Popup width token 410 px. App icon, summary/body, timestamp, count/expand affordance and horizontal actions get distinct roles. Hover controls timeout; drag dismissal animated. Do not port its timer/persistence implementation without independent lifecycle review.

## Reusable styling rules inferred from code

- Palette: Material-like *role* tokens, not same accent on everything: background, surface-container-low, container, high/highest, on-surface, on-surface-variant, primary/secondary containers and outline. Default dark samples: `#141313` background; `#1c1b1c` low; `#201f20` container; `#2b2a2a` high; `#363435` highest; `#e6e1e1` on-surface; `#cbc5ca` secondary text; `#cbc4cb` primary. These are upstream defaults, **not colors to force** over our theme-manager palette. Use contrast-sensitive semantic mapping from active theme.
- Opacity is restrained: surfaces generally opaque; appearance system *can* opt into configured transparency and selectively solves layer overlays. Blur/translucency are not global design shorthand. Reserve artwork glass for direct image overlays, keep text cards legible and opaque.
- Shape ladder: 8 very-small, 12 small, 17 normal, 23 large, 30 very-large px; full-pill for pills. Container > nested item > button radii. Avoid single radius everywhere.
- Type ladder: 10, 12, 13, 15, 16, 17, 19, 22–23 px; title weight ~550, body ~450, icon glyphs separate. Small metadata subdued, short summaries strong, body secondary; use elision and explicit content bounds.
- Spacing: 3–5 px tight relationships inside lists, 10 px card inset/row gap, larger region gaps for independent panels. 410 px popup vs 460 px sidebar keeps line lengths controlled. Animate purposeful entry/expand/dismiss; source has ~200 ms effects, 350 ms small spatial, 500 ms default spatial motion.
- **User preference: no borders on UI elements.** Establish hierarchy with opaque surface colors, spacing, radius, typography and hover/selected fills; do not rely on outlines for cards, fields, panels or controls. Critical urgency uses contrasting fill, not border. Focus remains visible via fill and caret.

## Current implementation gaps and application

- `shell.qml:33-61,265-297` has one `popupNotification` and one 5500 ms timer: every new arrival replaces prior popup. Popup requests `WlrKeyboardFocus.OnDemand`, likely source of unwanted focus shifts. Swap for bounded concurrent entries with per-entry timeouts/hover pause; passive stack must request `WlrKeyboardFocus.None`. Inline reply needs explicit interaction path that does not steal focus upon appearance; do not silently remove reply feature. Test actual compositor focus, not only static QML.
- `NotificationCard.qml` uses uniform 12 px radius, 12 px inset, always-drawn outline and generic button chips. Redesign information hierarchy using existing theme tokens, adaptive height, better app identity, calmer metadata, stronger headline and restrained urgency. Keep actions, icons/images, numeric progress and inline reply functional. Notification center in `shell.qml:445-516` should share card language, grouping optional after stack/focus correctness.
- Existing surface palette in `shell.qml:165-176` follows theme snapshot. Refine tokens rather than hardcoding upstream charcoal, and keep desktop free of permanent bar. Extend visual coherence to launcher/dashboard/studio in separate stages after notification regressions fixed; requires manual screenshot comparison at actual screen sizes.
- `wallpaper_sources.py:58-61,139-141` already supports Unsplash via `UNSPLASH_ACCESS_KEY` in Quickshell **process environment**; user says keys ready, but location/inheritance unverified. Never print or commit token. Verify presence only (boolean), test search and download tracking without exposing credential. No need to add provider anew.

## Local implementation and validation status

Current shell uses a maximum-three popup stack, independent hover-paused timers, passive `WlrKeyboardFocus.None`, and deliberate reply focus. Center/cards share theme-mapped opaque surface tiers and 17/23 px radius ladder; other panels got matched spacing/radius. `qmllint` and 13 Python tests passed. Four `notify-send` events preserved focused `virt-manager` address; Hyprland reported a 410×415 popup layer. One earlier focus measurement coincided with a fullscreen layout change and was inconclusive. No screenshots or manual pointer/reply test have been reviewed; design polish and interaction acceptance remain provisional. Running Quickshell process lacks `UNSPLASH_ACCESS_KEY`, despite user's statement that keys are ready: launcher environment inheritance needs configuration, without exposing secret.

## Acceptance checklist for redesign

1. At least three simultaneous notifications visible in bounded top-right stack; individual expiry and hover pause; repeated/replaced IDs do not create duplicates; overflow remains in history.
2. Arrival does not change focused Hyprland client or intercept keyboard; clicking popup actions/reply remains possible, with focus obtained only by explicit interaction where required.
3. Compact and expanded/center cards readable with long text, picture, progress, urgency, action overflow and low resolution; no clipping; theme light/dark legible.
4. IPC, DBus ownership, notification dismiss/history and DND behavior preserved; QML lint and manual screen tests pass. Confirm Unsplash key availability without revealing value.
