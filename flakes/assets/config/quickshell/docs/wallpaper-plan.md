## Wallpaper studio — revised scope

1. **Theme-file assignment:** Image/video choice edits selected theme’s `WALLPAPER=` atomically, backs up original, validates path/theme, reapplies active theme, confirms snapshot. Current theme files include broken `walls/api/*` references; flag missing paths.
2. **Full-width studio:** Separate wallpaper window; wide cinematic image strips or connected skewed parallelogram tiles, with selection-driven animation and large preview. Local categories map to directories under `~/Pictures/walls`; import, move, recategorize; delete requires confirmation and reference protection. Web results get preview before download.
3. **Discovery:** Unsplash (requires developer API key and attribution/download tracking), Wallhaven (public API; optional key for gated content), Reddit (OAuth/API policy permitting), plus openly licensed Wikimedia Commons/Pexels/Pixabay when credentials available. Display source/license/attribution, high-res filters; avoid bypassing API access, rate limits or unclear reuse rights. Source availability contingent on valid credentials and provider policy.
4. **Video:** Include local videos and API-supported web video results; generate still previews with ffmpeg, play selected video only. `mpvpaper` is installed; integrate per-monitor video compositor via supervised process, stop/replace on wallpaper/theme change; static Quickshell background and Hyprlock use generated still for video. Avoid changing desktop renderer until tested with current Hyprland setup.
5. **Validation:** Backend unit tests for path traversal, atomic theme edits, image/video validation, provider error handling, and theme references. QML lint/reload plus visual interaction tests, video lifecycle, and lock still frame.

Implementation in slices: backend/theme integrity → gallery/preview → discovery → video plumbing → integration tests. Decisions: initial categories are existing directories; user explicitly requested import/move/categorize, high quality web sources, wide playful animation, and video. Deletion handled only with explicit confirmation.
