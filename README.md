# Dotfiles

Personal dotfiles managed with symlinks and a repeatable bootstrap script.

## Fresh machine setup

Clone this repo anywhere you like, then run the full bootstrap:

```bash
git clone https://github.com/adrsha/dots ~/dots
cd ~/dots
./setup.sh --all --theme-manager
```

That command is safe to run again. It links every supported config, registers the
actual clone path in `~/.config/dots/path`, and installs the theme commands to
`~/.local/bin` when Rust/Cargo is available.

If a machine already has configs and you want this repo to replace them, run:

```bash
./setup.sh --all --force --theme-manager
```

Use `--force` carefully: it removes existing target files/directories before
linking this repo's versions.

## Selective setup

Install only specific components without prompts:

```bash
./setup.sh fish nvim ghostty
```

Or run interactively:

```bash
./setup.sh
```

Supported components:

- `hypr`
- `ghostty`
- `nvim`
- `fish`
- `vicinae`
- `vicinae-themes`
- `lsd`
- `swaync`
- `zathura`
- `firefox-colors`
- `scripts`

## Theme manager

Install or update the theme binaries with:

```bash
./setup.sh --theme-manager --no-prompts
```

Use themes from fish:

```fish
theme kanagawa
theme everblush
```

The theme manager finds this repo through, in order:

1. `$DOTS_DIR`
2. `~/.config/dots/path` generated by `setup.sh`
3. `~/dots`
4. `~/.dots`

That means the repo can be cloned to a different path on each computer without
breaking theme generation.

## What gets linked

- Hyprland config → `~/.config/hypr`
- Ghostty config → `~/.config/ghostty`
- Neovim config → `~/.config/nvim`
- Fish config → `~/.config/fish/config.fish`
- Vicinae config → `~/.config/vicinae`
- Vicinae themes → `~/.local/share/vicinae/themes`
- lsd config → `~/.config/lsd`
- swaync config → `~/.config/swaync`
- zathura config → `~/.config/zathura`
- Firefox colors → `~/.config/firefox-colors`
- Scripts repo → `~/Scripts`

## NixOS

`configuration.nix`, `flake.nix`, and `hardware-configuration.nix` are included,
but `hardware-configuration.nix` is machine-specific. Do not blindly reuse one
host's hardware file on another host.
